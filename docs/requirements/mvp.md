# MVP Requirements

## ผู้ใช้งานและงาน

### REQ-WORKFLOW-001 สร้างงานประเมิน
**เมื่อ** ผู้ประเมินเปิดระบบ **ผู้ใช้ต้อง** สร้างงานด้วยเลขที่งาน วันที่ลงพื้นที่ ผู้ว่าจ้าง และธนาคารปลายทางได้

**เกณฑ์ยอมรับ**
- แสดงแบบฟอร์มข้อมูลเริ่มต้นและสถานะ `แบบร่าง`
- เลขที่งานและวันที่แก้ไขได้ภายหลังในแบบร่าง

### REQ-WORKFLOW-002 บันทึกงาน
**เมื่อ** ผู้ประเมินกรอกหรือแก้ไขข้อมูล **ระบบต้อง** บันทึกข้อมูลล่าสุดไว้ในเครื่องโดยอัตโนมัติ และมีปุ่มบันทึกด้วยตนเอง

**เกณฑ์ยอมรับ**
- เปิดหน้าใหม่ในเบราว์เซอร์เดิมแล้วกู้คืนข้อมูลล่าสุดได้
- การเริ่มงานใหม่ต้องขอการยืนยันก่อนล้างข้อมูล

## ข้อมูลทรัพย์สิน

### REQ-PROPERTY-001 บันทึกข้อมูลบ้านและที่ตั้ง
ระบบต้องรองรับที่อยู่แบบข้อความ ละติจูด ลองจิจูด ประเภททรัพย์ สภาพ เนื้อที่ดิน พื้นที่ใช้สอย จำนวนชั้น ปีที่สร้าง จำนวนห้องนอน ห้องน้ำ และรายละเอียดเพิ่มเติม

### REQ-PROPERTY-002 แสดงหน่วยข้อมูล
ระบบต้องแสดงหน่วย `ตร.วา`, `ตร.ม.`, `บาท` และเก็บตัวเลขเป็นค่าที่ไม่ติดสัญลักษณ์คั่นหลักพัน

## รูปถ่ายและหลักฐาน

### REQ-PHOTO-001 เพิ่มรูปหลักฐาน
ผู้ประเมินต้องเพิ่มรูปภาพหลายรูปจากอุปกรณ์ และระบบต้องแสดงภาพตัวอย่างก่อนพิมพ์รายงาน

### REQ-PHOTO-002 ลบรูปหลักฐาน
ผู้ประเมินต้องลบรูปที่เลือกได้ก่อนบันทึกหรือพิมพ์รายงาน

## การประเมินราคา

### REQ-VALUATION-001 รองรับวิธีประเมิน
ระบบต้องรองรับ 3 วิธี: ผู้ประเมินกรอกเอง, พื้นที่ใช้สอยคูณราคาต่อตารางเมตร, และกรอกราคาจากทรัพย์เปรียบเทียบ

### REQ-VALUATION-002 แสดงที่มาของราคา
ระบบต้องแสดงราคาประเมินและคำอธิบายวิธีคำนวณที่เลือก เพื่อให้ผู้ตรวจสอบเข้าใจที่มาของผลลัพธ์

## รายงาน

### REQ-REPORT-001 พิมพ์รายงาน
ผู้ประเมินต้องสั่งพิมพ์งาน และเลือกปลายทางเป็น PDF ได้จากกล่องพิมพ์ของเบราว์เซอร์ โดยรายงานต้องมีข้อมูลทรัพย์และรูปภาพ

### REQ-REPORT-002 ระบุข้อจำกัดการส่งธนาคาร
Prototype ต้องแสดงให้ผู้ใช้ทราบว่าข้อมูลยังไม่ถูกส่งไปธนาคารจริง จนกว่าจะมีการยืนยัน API หรือแบบฟอร์มของธนาคารเป้าหมาย

## ข้อกำหนดระยะถัดไป
- `REQ-REVIEW-001`: ผู้ตรวจสอบขอแก้ไขหรืออนุมัติงาน พร้อมประวัติการเปลี่ยนสถานะ
- `REQ-EXPORT-001`: ส่งออก Excel/CSV ตาม schema ของธนาคาร
- `REQ-INTEGRATION-001`: ส่งข้อมูลผ่าน API ของแต่ละธนาคาร โดยมี authentication และการติดตามผล
- `REQ-SECURITY-001`: login, role-based access, audit log, encryption, retention และคำขอเกี่ยวกับข้อมูลส่วนบุคคล
- `REQ-PIPELINE-001` ถึง `REQ-PIPELINE-006` และ `REQ-ROLE-001`: สายงาน 3 ทีม A → B → C ดูรายละเอียดใน [pipeline.md](pipeline.md)
- ดึงงานจากธนาคารและส่งผลกลับด้วย API หรือ RPA แทนการกรอกมือของทีม A และทีม C
